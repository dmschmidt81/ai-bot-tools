# Public Artifact Review Checklist

Use this checklist before publishing a new artifact or moving material from a private repository into this public portfolio.

## 1. Purpose

- [ ] The artifact demonstrates a specific portfolio skill.
- [ ] The public version contains only the detail needed to demonstrate that skill.
- [ ] The artifact is clearly labeled as a public snapshot when a private production version exists.

## 2. Privacy and Secrets

- [ ] No passwords, API keys, tokens, recovery codes, certificates, or private keys.
- [ ] No unnecessary student, employee, applicant, family, health, financial, or other sensitive personal information.
- [ ] No screenshots, logs, or examples containing hidden identifiers or credentials.
- [ ] Live internal URLs and organization-specific resources are removed unless intentionally public.

## 3. Authorization and Operations

- [ ] Public examples do not imply authorization to send, publish, deploy, delete, or modify external systems.
- [ ] Human approval gates remain clear where consequential actions are discussed.
- [ ] Production permissions are not represented as prompt-only safeguards.

## 4. Evaluation Integrity

- [ ] Dry runs, simulations, and deployed runtime tests are labeled distinctly.
- [ ] No result is described as observed unless it was actually observed.
- [ ] No security review is described as a penetration test unless one occurred.
- [ ] Limitations and residual risks are stated where material.

## 5. Third-Party and IP Review

- [ ] No unnecessary proprietary tests, answer keys, scoring guides, or confidential source material.
- [ ] Generated examples are original when possible.
- [ ] Third-party names or trademarks are not presented as endorsements.
- [ ] The intended reuse/license terms are clear.

## 6. Prompt-Injection and Data Boundary

- [ ] Untrusted content is treated as data rather than authority.
- [ ] Retrieved documents cannot silently expand permissions.
- [ ] Public specifications do not expose credentials or live tool configuration.

## 7. Final Recheck

- [ ] Links work and point only to intended public resources.
- [ ] Dates, names, and claims are accurate.
- [ ] The artifact does not expose more of the current private implementation than intended.
- [ ] The corrected artifact has been re-reviewed after edits.
